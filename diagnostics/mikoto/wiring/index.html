A virtual pair of hands
for your Mikoto.

Five signal connections, five 1 kΩ resistors and shared ground. The SuperMini pulls reset and four keyboard inputs low, then lets go of each wire when the action finishes.

Install the updated SuperMini code before attaching signal wires. Disconnect all five signal wires while replacing the earlier firmware. The new code uses open-drain outputs; the previous transistor version uses different signal polarity.

Your target: Mikoto revision 7.2. Use mikoto-test-7.2.0.uf2. The Mikoto test image still uses the same four inputs.

Direct connections, with one resistor each

Reset and key presses mean connect to ground. On release, the SuperMini stops driving the signal; the Mikoto's own pull-up restores the high level. This is called open-drain operation. The diagram shows selected connections, not the physical positions of the controller pads. Find the matching printed GPIO labels.

The 1 kΩ resistors limit current if a Mikoto signal is accidentally configured as an output. They do not make the inputs 5 V tolerant or permit wiring to an unpowered controller.

Parts to gather

5 × 1 kΩ¼ W series resistors
12 jumper wires10 signal jumpers + 2 grounds
2 × USB data cablesOne cable per controller

Use a breadboard with at least 22 numbered rows for the resistors and ground strip, plus space or adapters for both controllers. A standard 400-point or 830-point board is suitable for the resistor section. No external transistors, keyboard diodes or extra pull-up resistors are needed for these four independent inputs.

Connect a SuperMini GND directly to a Mikoto GND. Each signal goes through its own resistor. On the SuperMini, the firmware refers to board.P0_06, etc. D1–D4 are ZMK connector names on the Mikoto; use its printed P0.xx labels for wiring.

Breadboard placement

Orient the breadboard with letters a–j across and increasing row numbers downward. Put each resistor across the center gap, between columns e and g on the same numbered row. Its legs must land in separate connected strips. Either direction is fine for a resistor.

Leave every positive power rail empty. Do not join VBUS, RAW, EXT_5V, VDD, VDDH, VCC or battery pins between the controllers. This design uses a numbered strip for ground, so there is no reliance on a breadboard's potentially split power rails.

Connect and test in stages

  1. With all inter-board signal wires removed, install the updated SuperMini Python files and reset it. If CircuitPython 10.3.1 is already installed, its UF2 runtime does not need reinstalling. The setup guide explains both fresh setup and migration.
  2. Inspect the unpowered boards and fit the five resistors. Connect shared ground first. Leave the five signal wires unattached while plugging both boards into USB.
  3. With both boards powered, check the SuperMini's status reply for mikoto-fixture-v2 and direct-open-drain. Attach only the reset signal through R0, then run the bootloader command. Expect the Mikoto boot drive with the correct Board-ID.
  4. Install the Mikoto 7.2 test image. With both controllers still powered and the fixture idle, attach the four key signals through R1–R4, then run the automated test.
  5. Before unplugging either USB cable, disconnect all five signal wires. An unpowered controller can receive unwanted current through its GPIO protection circuits. The 1 kΩ resistors are current limits, not power-off isolation.
Both controllers must remain powered during testing. Never supply 5 V to reset or a GPIO. If a board gets hot or trips USB power, remove its power and inspect it before continuing.

What gets checked

The laptop tool observes F13–F16 press and release events from the device named Mikoto Test. F keys can still trigger custom shortcuts, so close applications that bind them. Passing tests the four GPIO/header paths and USB keyboard reporting under these conditions. Bluetooth, charging, output drive and other pins remain separate tests.

These are independent input-to-ground keys. A scanned matrix would need switches between rows and columns and a different fixture. A failed test can be caused by wiring, a resistor, firmware selection, laptop permissions or the Mikoto.
