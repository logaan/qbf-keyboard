QBF · controller diagnostic fixture · 13 October 2026

A virtual pair of hands
for your Mikoto.

The SuperMini briefly connects reset and four keyboard inputs to ground. Your laptop sends the commands, copies firmware to the Mikoto and checks the resulting USB keyboard events.

Reset means connect to ground. Do not supply voltage to RESET. Both boards use their own USB cables. Connect GND between them; leave every power pin and the batteries disconnected from this fixture.

Five electronic switches

The drawing shows the selected connections, not the physical positions of the controller pads. Find the matching printed GPIO labels on each board. A high SuperMini output turns its transistor on; the Mikoto sees a low input. The fixture itself sends no keyboard events.

B = base (control), C = collector (Mikoto side), E = emitter (ground). The 100 kΩ resistor connects B to E. Use onsemi 2N3904 TO-92 parts and confirm the lead numbers in their datasheet; the drawing is an electrical symbol.

Parts to gather

5 × 2N3904NPN transistors
5 × 4.7 kΩBase resistors
5 × 100 kΩBase pull-down resistors
5 × 1 kΩCollector resistors

Also: a breadboard with at least 45 numbered rows for the five switch circuits (a standard 830-point board is suitable), jumper wires, two USB data cables, and separate breadboard space or adapters for the controllers. Use ¼ W resistors. No keyboard diodes or external pull-up resistors are needed for these four independent inputs.

Repeat one circuit five times

Orient the central breadboard with letters a–j across and increasing row numbers downward. Spread each transistor's leads along three separate rows, all in column b. Never put E, B and C in the same numbered a–e strip: that shorts them together. Bend the leads gently to fit; identify them first.

Join each emitter jumper to the same ground rail. Join a SuperMini GND and a Mikoto GND to that rail. If the rail is split halfway along the breadboard, bridge its two ground segments with a jumper and verify continuity. Leave the positive rail empty.

Build and test in stages

  1. Unplug USB and disconnect batteries. Inspect the Mikoto for solder bridges. Confirm that neither board's supply pins are connected to this fixture. A board that gets hot or trips USB power needs physical inspection before continuing.
  2. Load the supplied CircuitPython UF2 and three Python files onto the SuperMini. This one-time step needs a double reset of the SuperMini itself. Check its bootloader version first; use the setup guide.
  3. Build only Q0 first. Connect shared ground, plug both boards in, then run the bootloader command. Expect a MIKOTO-BOOT drive with the correct INFO_UF2.TXT Board-ID.
  4. Install the matching Mikoto test UF2 using the laptop command. Unplug both USB cables, add Q1–Q4, recheck the circuit, then reconnect.
  5. Run the automated HID test. It checks F13–F16 press and release events from the device named Mikoto Test. F keys can still trigger user-configured shortcuts; close applications that bind them.
This tests direct keys. Each key input has a firmware pull-up and is independently pulled to ground. This wiring does not close switches between scanned matrix rows and columns. A full matrix needs a different switching arrangement.

What the result tells you

If UF2 mode works, the target can run its bootloader and communicate over USB. If all four HID tests pass, those four GPIO/header paths and USB keyboard reporting work under this test. A failure can still be caused by a wire, resistor, transistor, wrong firmware revision, host permission or the Mikoto itself. Bluetooth, charging and untested pins are separate tests.
